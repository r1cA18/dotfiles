# Skill Quality Rubric

7次元評価。各次元 1-5 点、重み付き合計で最大 35 点。

## 採点方法

- 各次元を 1-5 で採点（整数のみ）
- 重み付きスコア = raw score x weight
- 合計 = 全次元の重み付きスコアの和
- スキルの複雑さに応じて適正水準が変わる（Simple スキルに Structure 5 は不要）

## グレード

| Grade      | Score | 意味                           |
| ---------- | ----- | ------------------------------ |
| Excellent  | 28+   | 本番品質。手本として参照できる |
| Good       | 21-27 | 実用十分。軽微な改善余地あり   |
| Needs Work | 14-20 | 構造的な問題あり。改善推奨     |
| Weak       | <14   | 大幅な改修が必要。再設計を検討 |

---

## Dimension 1: Structure (Weight: 1.0)

スキルの複雑さに見合ったディレクトリ構成を持っているか。

| Score | 基準                                                        |
| ----- | ----------------------------------------------------------- |
| 1     | SKILL.md のみ。複雑な機能なのに補助ファイルなし             |
| 2     | SKILL.md のみだが、スキルの用途がシンプルなので許容範囲     |
| 3     | references/ OR scripts/ がある                              |
| 4     | references/ + scripts/ or templates/ がある。構成が明確     |
| 5     | 用途に最適な構成（router+sub-skills、reference-library 等） |

**注意**: Simple スキル（CLI ラッパー等）は SKILL.md のみでも 2-3 点が適正。
構成の豪華さではなく、複雑さに見合っているかで判断する。

---

## Dimension 2: Frontmatter (Weight: 1.0)

YAML frontmatter の質。description がトリガーの精度を決める最重要フィールド。

| Score | 基準                                                          |
| ----- | ------------------------------------------------------------- |
| 1     | frontmatter なし、または name のみ                            |
| 2     | description あるが短い/曖昧。"when" が不明確                  |
| 3     | description が what + when を含む。基本的なトリガーワードあり |
| 4     | EN + JA triggers あり。allowed-tools 指定あり                 |
| 5     | "pushy" な description。多様なトリガーフレーズ。metadata あり |

**チェックポイント**:

- [ ] name がディレクトリ名と一致
- [ ] description が「何をするか」と「いつ使うか」の両方を含む
- [ ] 日本語トリガー（「〜して」形式）がある
- [ ] 英語トリガーがある
- [ ] allowed-tools が適切に制限されている（指定なし = 全ツール許可）
- [ ] user-invocable が意図通りに設定されている

---

## Dimension 3: Instructions (Weight: 1.5)

SKILL.md body の指示品質。エージェントが迷わず実行できるか。

| Score | 基準                                                             |
| ----- | ---------------------------------------------------------------- |
| 1     | 曖昧な説明のみ。何をすべきか不明確                               |
| 2     | 手順はあるが「何を」だけで「なぜ」「どうやって」がない           |
| 3     | 明確なステップ。imperative form。基本的なエラーケース考慮        |
| 4     | progressive disclosure。エラー処理。判断基準が表で整理されている |
| 5     | 自律的修正ループ。ハマりポイント表。コスト意識。実績知の凝縮     |

**良い指示の特徴**:

- imperative form（「〜する」「〜を実行」）、説明口調ではなく命令口調
- 「なぜそうするか」の理由が書かれている
- エラー時のフォールバックが定義されている
- 表で判断基準が整理されている（FFmpeg vs FrameScript の使い分け等）
- progressive disclosure: 全部を最初に読ませず、必要時に references を参照

---

## Dimension 4: References (Weight: 1.0)

参照資料（references/、scripts/、templates/ 内のファイル）の質と量。

| Score | 基準                                                           |
| ----- | -------------------------------------------------------------- |
| 1     | 必要なのに参照なし（複雑なドメインでインライン説明のみ）       |
| 2     | 参照があるが質が低い（古い、不完全、SKILL.md と重複）          |
| 3     | 適切な参照がある。各ファイルの役割が明確                       |
| 4     | ドメイン特化の参照。トラブルシューティング。実行可能スクリプト |
| 5     | テンプレート + スクリプト + 参照ガイド。再利用可能な資産       |

**注意**: Simple スキルは参照不要なので 3 が適正上限。
参照の量ではなく、必要なものが揃っているかで判断。

**チェックポイント**:

- [ ] 各参照ファイルが 300 行以下（超える場合は TOC あり）
- [ ] SKILL.md との内容重複がない
- [ ] スクリプトがある場合、実行可能で動作確認済み
- [ ] テンプレートがある場合、プレースホルダーが明確

---

## Dimension 5: Actionability (Weight: 1.5)

スキルが実際に「実行」するか、それとも「説明」するだけか。

| Score | 基準                                                   |
| ----- | ------------------------------------------------------ |
| 1     | 知識の羅列のみ。実行手順なし                           |
| 2     | 手順はあるがコマンド例なし。抽象的                     |
| 3     | コマンド例あり。基本的な実行は可能                     |
| 4     | スクリプト or テンプレートで自動化。コピペで動く       |
| 5     | Build Loop パターン。自律的修正。テンプレート複製+置換 |

**実行駆動の原則**: 「手順を説明する」のではなく「実行する」。
スキルの目的が「知識提供」（reference-library 型）の場合は 3 が適正上限。

---

## Dimension 6: Deduplication (Weight: 0.5)

他のスキルとの重複がないか。

| Score | 基準                                         |
| ----- | -------------------------------------------- |
| 1     | 別スキルとほぼ同一内容（コピペ）             |
| 2     | 大幅な重複がある（70%以上の内容が類似）      |
| 3     | 部分的な重複があるが、独自の価値もある       |
| 4     | 軽微な重複のみ。境界が明確                   |
| 5     | 完全にユニーク。関連スキルとの役割分担が明確 |

**検出方法**:

- description の類似度チェック（キーワード重複）
- SKILL.md body の内容比較
- 同じドメインの別スキルがないか確認

---

## Dimension 7: SDK Readiness (Weight: 0.5)

`claude -p` やSDK経由で使用できるか。trigger description の質。

| Score | 基準                                                               |
| ----- | ------------------------------------------------------------------ |
| 1     | description が曖昧でトリガーされない                               |
| 2     | 基本的なキーワードでトリガーされるが、false positive/negative 多い |
| 3     | 適切なトリガー。基本的なプロンプトで呼び出せる                     |
| 4     | 多様なフレーズでトリガー。false positive が少ない                  |
| 5     | trigger smoke test 済み。evals が書ける品質の description          |
