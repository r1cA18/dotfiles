起動方法

試用版は NVIM_APPNAME で既存の設定と分けてあります。次のcommandで起動します。

NVIM_APPNAME=nvim-next nvim

いつもの nvim は、これまでどおり既存の設定で起動します。2つは設定・plugin・履歴のすべてが別々なので、片方を壊してももう片方に影響しません。

対象既存試用版
設定~/.config/nvim~/.config/nvim-next (~/dotfiles/nvim-next へのsymlink)
pluginとparser~/.local/share/nvim~/.local/share/nvim-next
履歴とlog~/.local/state/nvim~/.local/state/nvim-next

毎回打つのが手間な場合は、shellで一時的にaliasを定義してください。

alias nv='NVIM_APPNAME=nvim-next nvim'

<leader> はSpace keyです。このpageの <leader>ff は「Space、f、f の順に押す」という意味です。<C-n> はCtrlを押しながらn、<CR> はEnter、<BS> はBackspace、<M-q> はOption (Alt) を押しながらqです。

最初の5分で試すこと

  1. 引数なしで起動し、起動画面で f を押してfileを開きます
  2. <leader> を押して少し待ち、出てくるkeyの一覧を眺めます
  3. - でdirectoryを開き、<CR> で別のfileへ移ります
  4. 関数名の上で K を押し、LSPの説明を見ます
  5. s の後に画面内の文字を2字打ち、labelを押してjumpします

設定の読み方と消し方

設定は ~/dotfiles/nvim-next/ にあります。1つのfileが1つの役割を受け持ち、そのpluginのkeymapと設定も同じfileに書いてあります。

nvim-next/
  init.lua               leaderを決めて config/ を読み込むだけです
  lazy-lock.json         pluginの版 (commit) の固定です
  lua/config/
    options.lua          Neovimの既定から変える値だけです
    keymaps.lua          pluginに依存しないkeymapだけです
    autocmds.lua
    lazy.lua             lazy.nvimの準備と lua/plugins/ の読み込みです
  lua/plugins/
    <役割>.lua           役割ごとのpluginと、そのkeymapと設定です

pluginを消す手順

  1. lua/plugins/<役割>.lua を削除します。迷っている間は、lua/plugins/ の外へ移動するだけでも同じ効果があります
  2. Neovimを起動し直し、:Lazy clean を実行します。pluginの実体と lazy-lock.json の該当行が消えます

役割fileは互いに依存していないので、どのfileを消しても他の機能は動き続けます。26個すべてについて、1つずつ外した状態でerrorなく起動することを確認してあります。

pluginを足す手順

  1. lua/plugins/<役割>.lua を作り、pluginのspecを返します。keymapは keys に書きます
  2. Neovimを起動し、:Lazy install を実行します

:Lazy で、入っているpluginと読み込み状況の一覧を見られます。更新は :Lazy update です。自動では更新されません。

役割ごとの章

26の役割を5つのまとまりに分けてあります。各章の「まず試す操作」を実際に行い、最後の欄に判定を記録してください。判定はこのbrowserに保存され、判定のまとめに集計されます。

最終commitの日付は2026-11-10に確認したものです。

fzf-lua/最終commit 2026-11-08

file操作

oil.nvim/最終commit 2026-10-11

directoryを普通のbufferとして開きます。行を編集して :w すると、その編集がrename・移動・削除・作成として実行されます。削除したfileはゴミ箱へ移動します。

まず試す操作
  1. - で今のfileがあるdirectoryを開きます。もう一度 - で親へ上がり、<CR> で開きます
  2. file名の行を書き換えて :w するとrenameされます。確認窓が出るので y で実行します
  3. o で新しい行にfile名を書き :w すると作成されます。末尾を / にするとdirectoryになります
  4. dd で行を消して :w すると削除されます。別のdirectoryへ p で貼ると移動になります
  5. <leader>e で浮いた窓として開きます。g? でkey一覧、g. で隠しfileの表示切替、<C-p> でpreviewです
設定file
nvim-next/lua/plugins/files.lua
消す方法
nvim-next/lua/plugins/files.lua を削除します。その後 :Lazy clean を実行します。
消した後
- と <leader>e が無くなり、nvim <directory> はbuiltinのnetrwで開くようになります。
代替候補
  • mini.files (列表示で編集)
  • neo-tree.nvim (tree表示)
  • yazi.nvim (外部filerを呼ぶ)
  • builtinのnetrw
判定

画面内jump

消した後

format

conform.nvim/最終commit 2026-08-11

保存時にformatterを実行します。Luaは stylua、Nixは nixfmt、shellは shfmt を使い、それ以外はLSPのformat機能に任せます。formatterのbinaryはNixが供給します。

まず試す操作
  1. Lua fileのindentをわざと崩して :w すると整形されます
  2. <leader>cf で保存せずに整形します。visual modeでは選択範囲だけを整形します
  3. <leader>uf で保存時formatのon / offを切り替えます
  4. :ConformInfo で今のbufferに使われるformatterと状態を確認します
設定file
nvim-next/lua/plugins/format.lua
消す方法
nvim-next/lua/plugins/format.lua を削除します。その後 :Lazy clean を実行します。
消した後
保存時の自動formatが無くなります。LSPのformatは :lua vim.lsp.buf.format() で呼べます。
代替候補
  • LSPのformatだけを使う
  • conformからtreefmtを呼んでNix側の定義に一本化する

読む・理解する

LSP

nvim-lspconfig/最終commit 2026-11-10

LSP client自体はNeovimのbuiltinです。nvim-lspconfigはserverごとの起動定義を提供するだけで、有効にするserverは vim.lsp.enable() の一覧で決めます。serverのbinaryはNixが供給します。有効なserverは bashls / biome / cssls / html / jsonls / lua_ls / marksman / nixd / taplo / vtsls / yamlls です。

まず試す操作
  1. 関数名の上で K を押すと説明が出ます
  2. grn でrename、gra でcode action、grr で参照一覧です (builtinのkeymapです)
  3. <C-]> で定義へjumpし、<C-t> で戻ります
  4. <leader>uh でinlay hintの表示を切り替えます
  5. :checkhealth vim.lsp で接続中のserverを確認します
設定file
nvim-next/lua/plugins/lsp.lua
消す方法
nvim-next/lua/plugins/lsp.lua を削除します。その後 :Lazy clean を実行します。
消した後
LSPがすべて止まります。補完のLSP候補・diagnostics・LSP経由のformatも無くなります。
代替候補
  • nvim-lspconfigを使わず lsp/<server>.lua を自分で書く

treesitter highlightとfold

nvim-treesitter (checkoutのみ)/最終commit 2026-11-07

構文解析に基づく色分けと折りたたみを有効にします。色分け自体はbuiltinの vim.treesitter.start() です。nvim-treesitterはpluginとしては読み込まず、parserの版の一覧とquery集として使います。parserは scripts/build-parsers.lua がcompileします (暫定の方法です。READMEを参照してください)。

まず試す操作
  1. .nix や .ts を開き、色分けされていることを確認します
  2. :InspectTree で構文木を表示します。:Inspect はcursor位置のhighlight groupを表示します
  3. za で折りたたみを開閉します。zM ですべて閉じ、zR ですべて開きます
  4. visual modeで an を押すたびに選択が外側の構文へ広がり、in で内側へ戻ります (0.12のbuiltinです)
設定file
nvim-next/lua/plugins/syntax.lua
消す方法
nvim-next/lua/plugins/syntax.lua を削除します。その後 :Lazy clean を実行し、nvim-next/scripts/build-parsers.lua と ~/.local/share/nvim-next/site/ も削除します。
消した後
追加したparserの色分けと折りたたみが無くなり、正規表現ベースの色分けに戻ります。Neovim同梱のparser (lua / markdown / vimなど) は残ります。
代替候補
  • Nixでparserとqueryを供給する (本採用時の案)
  • nvim-treesitterのinstallerを使う (tree-sitter CLIが必要)
判定
