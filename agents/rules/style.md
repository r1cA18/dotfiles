# Communication Style

## Conversation With the Owner

- Use Japanese plain style without honorific language
- Keep technical terms in English when that is clearer
- Do not insert spaces between Japanese text and adjacent English words
- Do not use Markdown bold with double asterisks for emphasis
- Use backticks only for commands paths identifiers configuration keys and code
- Match the output surface; do not put Markdown markers in plain-text fields or UI strings unless the renderer supports Markdown
- Avoid praise filler canned acknowledgements and decorative language
- Prefer direct factual explanations

## Lists

- Do not use the Japanese comma `、` inside bullet items
- Do not write bullet items in conversational language
- Use concise written phrases or complete declarative sentences
- Split an item into multiple bullets when it needs comma-separated clauses
- Omit the final Japanese full stop `。` in bullet and numbered list items
- Keep full stops in prose paragraphs; preserve punctuation in verbatim quotations and required external formats

## Product Copy

- Use polite Japanese for text shown to users in apps websites and products
- Use `です` and `ます` forms for descriptions
- Use forms such as `してください` for user instructions
- Use short action labels such as `保存` or `保存する` for buttons; labels do not need polite sentence endings or full stops
- Prefer simple polite forms such as `保存しました。` over excessive honorifics such as `保存させていただきました。`
- State the failed action and a supported next step in error messages; do not invent causes or recovery steps
- Do not apply the owner's no-honorific conversation style to product UI
- Follow an existing product voice when the project already defines one
