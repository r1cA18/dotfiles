# Workflow

## Plan Mode

- 3ステップ以上のタスク、またはアーキテクチャに関わる変更は Plan mode で開始する
- Plan では「条件 → アクション」形式で具体的な実行手順を書く
- Plan の承認後に実装を開始する

## 検証

- テストが存在するプロジェクトでは、変更前にテストを実行し、変更後も実行する
- 動作確認せずに完了を宣言しない
- ビルドが必要な場合はビルドして通ることを確認する
- PR を push する前に、対象ブランチで lint / tsc をローカル実行して通ることを確認する

## TDD

- テスト可能な新機能にはテストを書く（推奨）
- バグ修正時は再現テストを先に書く（推奨）

## サブエージェント

- 独立した並列タスクはサブエージェントで分割を検討する
- 1サブエージェント = 1タスク（専門性を確保）
- 調査タスクは Explore エージェントで、実装は general-purpose で

## 自己改善の運用

学習内容の蓄積先は強度順に選択する:

| 種別               | 蓄積先                  | 例                                 |
| ------------------ | ----------------------- | ---------------------------------- |
| 自動防止できるもの | Hook (hooks/)           | 絵文字混入、秘密情報、巨大ファイル |
| 明示的な指示が必要 | Rule (rules/)           | コード規約、ワークフロー           |
| 複雑なドメイン知識 | Skill (skills/)         | Swift開発手順、動画編集            |
| セッション中の記録 | `40_AI/observations.md` | 発見、パターン、提案               |
| セッション詳細ログ | `40_AI/sessions/`       | 複雑な調査・探索の記録             |
| ユーザーの決定事項 | `40_AI/decisions.md`    | ワークフロー・ツール選定の記録     |

auto-memory は使用しない。全ての記録は vault 内の明示的な場所に書く。
CLAUDE.md に lessons を蓄積しない。version controlled な rules/ に昇格させる。
