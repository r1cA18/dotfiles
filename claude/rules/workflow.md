# Workflow

## Plan Mode

- 方針を左右する未確定事項がある場合はPlan modeを使う
- 実装範囲と検証方法を明確にする
- 既に任された範囲の実装や修正で承認を取り直さない

## サブエージェント

委譲の条件と担当範囲と統合責任は共有のAgent Orchestrationルールに従う。

- 読み取り中心の探索には利用可能なExploreを使う
- 範囲の明確な実装にはgeneral-purposeと`sonnet`を候補にする
- 難しい設計判断や原因分析には`opus`を候補にする
- 軽い独立確認には`haiku`を候補にする
- 指定済みの専門agent設定とユーザーのmodel指定を優先する
- model aliasが現在の接続先で使えない場合は親modelを継承する

modelの指定は利用中のtoolが提供する引数を使う。GPT proxy経由では接続先の対応を確認し、Anthropic向けaliasをそのまま強制しない。

## 自己改善の運用

作業の進捗と引き継ぎは共有のProgress Recordsルールに従い対象repoのdocsへ残す。
repoをまたいで再利用する個人の知見はvaultの既存配置へ保存する。

| 種別               | 蓄積先                  | 例                                 |
| ------------------ | ----------------------- | ---------------------------------- |
| 機械的に判定できる検査 | Hook (hooks/)        | 誤検知を確認済みの対象別検査 |
| 明示的な指示が必要 | Rule (rules/)           | コード規約、ワークフロー           |
| 複雑なドメイン知識 | Skill (skills/)         | Swift開発手順、動画編集            |
| セッション中の記録 | `40_AI/observations.md` | 発見、パターン、提案               |
| セッション詳細ログ | `40_AI/sessions/`       | 複雑な調査・探索の記録             |
| ユーザーの決定事項 | `40_AI/decisions.md`    | ワークフロー・ツール選定の記録     |

auto-memoryは使用しない。個人の知見はvault内の明示的な場所に書く。
CLAUDE.md に lessons を蓄積しない。version controlled な rules/ に昇格させる。

同じ問題が繰り返す場合は原因と適用範囲を確認して環境修正や既存rule・skillの改善を検討する。
観測回数だけで常時hookや共通制約を追加しない。
